# Contributing to the public Engineering distribution

Use a GitHub pull request for proposed changes. Keep examples synthetic and do
not include internal repository names, private operational evidence, populated
owner outcomes, credentials, or host-private authorization receipts.

Security vulnerabilities are not ordinary contribution feedback. Use the
repository's private vulnerability-reporting route described in `SECURITY.md`.

Every accepted change must preserve the documented Engineering contracts and
pass the repository's required checks. Maintainers retain merge, release,
installation, and activation authority as separate decisions.
